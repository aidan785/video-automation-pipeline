Rung two · constrain what it can reach
Scoped API keys
The flat rule: every API key is a scoped API key
Reason one
Scoping forces the question
What actions does this key actually need? You never drift into a prompt layer where a permission layer belongs
Reason two
One key per automation
Brightwater: the reminder system (Pillar 2) and the triage agent (Pillar 3). Two keys, each scoped to its own job
The free drill-down: runs per automation · cost per automation · its own log trail
Fixes four and five · wired into the build
Schema validation, reject on failure
Rung four
Define the exact shape of the output
Anything that doesn't match is rejected and flagged. Never repaired with a shrug and passed along.
Brightwater's routing form is the schema: category · urgency · route · draft · needs-human. Anything else, the run stops.
Rung five
The human gate, plus one monthly check
Look at the rejection rate
1,000 approvals in a row and 0 rejections: either the system is perfect, or your human is auto-approving everything
Rung seven · contain and recover
A feature flag per capability
The fix
A switch that turns one function off
without touching the rest
Brightwater: flag booking and reply sending separately from sorting. A misbehaving sender gets shut off while triage keeps working.
Flip each flag once, on purpose, before launch. Test the kill switch.

The rule above every fix
The model classifies, the code decides
The model
Reads messy input, says what kind of thing it is
The code
Plain, boring, deterministic. Takes the action.
Brightwater: the small model picks the category. Code routes the clinical ones to a human.
The safety rule lives in an if-statement, not in a paragraph of prompt
Seven fixes, one move: take what you were trusting the model to remember and hand it to something that can't forget

Fixes one to three · configuration only
No code. No budget conversation. An afternoon of work.
01
The capability inventoryOne written list: every tool, credential, and system the build can touch, and why it needs each one
Brightwater: look up · reschedule · escalate · one messaging channel · one scheduling system
If you can't explain why an agent holds a permission, remove it
Rung three · constrain what it can do
03
The read / write splitMark every credential that's read-only in practice but read-write in reality. Then split them.
Brightwater: lookup reads. Only the booking action writes.
Almost every system starts life with one full-scope key
The one-afternoon governance pass: inventory the capabilities · scope the credentials · split read from write
Rung six · verify and observe
06
A structured trace on every runWhat came in · what the model decided · what actions fired · what went out
Set it up on day one, while you're building the automation
Placement rule for sensitive data: the trace holds patient messages, so the logs live inside the practice's environment, not on your laptop
