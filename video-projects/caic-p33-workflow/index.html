The same line, drawn twice
Right once. Wrong once.
Decision one · Identity → code
Is the phone number in the member table?
A plain database lookup before any message reaches the agent. The model cannot get identity wrong, because the model is never asked.
Decision two · Escalation → prompt
"If they seem upset, hand off to a human"
No hard check behind the instruction. There was no binary rule to code against.
If the model didn't notice the anger, no escalation would happen
Was that the right call?
What I'd do today
A separate, specialized model up front: a dedicated sentiment analyzer reading the temperature first
Plus hard keyword triggers in code for the words that always mean escalation
More false alarms are better than missed escalations
A pinged human loses a minute. A furious customer who never reaches one loses the brand.

Zoom out · the same line at system scale
Workflow
You set the steps in code
The model fills in the smart parts at each step you defined
Agent
The model decides its own steps
And takes actions through the tools it holds
Most business builds should be workflows. Predictable beats impressive.
Never make the build more complicated just to get cool points
Inside a workflow · simplest to most complex

The test · can code take the job?
Completely binary · yes or no
Go code

Genuinely subjective
Model territory
Reading meaning, matching tone, weighing fuzzy situations. No binary rule exists to write down.
The confession · member privacy
Privacy lived in a prompt guardrail: "don't ever share one member's data"
It "worked" because nobody pushed hard on it
Run the rule: real data, real trust, and a binary rule was available
The right design: an admin-only agent behind the same hard gate as identity
My test · map the process, then look at each region
A
Binary decisions in a fixed orderKeep it deterministic, even with AI steps inside. That's just an AI workflow.
B
Decision points stacking up, loopsLogic that flows backwards, steps judged by the last one. That region earns an agent.
The cafe: scheduling earned one. Onboarding earned one. The rest should have stayed simple.
Our biggest architectural mistake: one master agent instead of split flows
Where it goes wrong · three ways
01
Building an agent because it sounds impressiveA chain of fixed steps ships faster, runs cheaper, breaks less
02
One master agent that does everythingSpecialized stations tell you which station to go fix
03
Safety rules in the prompt because it's easierMoney, data, or trust + a binary rule available: it goes in code
